# v1.5.0-beta.1 — Windows runtime validation

Статус: `Не выполнено`.

Этот план расширяет существующие MT-09, MT-10, MT-11, MT-12, MT-14 и MT-15 для `v1.5.0-beta.1`. Он не утверждает, что runtime-сценарии уже выполнены.

## Цель

Beta предназначена для реального Windows runtime-тестирования:

- DNS Health Failover;
- Split DNS / Windows NRPT;
- Agent / Named Pipe privileged path;
- self-contained installer на чистой Windows VM;
- исправления только фактически обнаруженных дефектов.

Tray customization уже merged и проверяется только smoke-сценарием MT-15.

## Ограничения

- Работать от актуального `main`.
- Не выполнять unrelated refactoring и не менять архитектуру без необходимости.
- Не ставить `PASS`, если сценарий реально не выполнялся.
- Destructive/network tests выполнять только на disposable Windows 11 x64 VM.
- Не трогать рабочую установленную копию DnsSwitcher на основной машине.
- Не создавать stable release `v1.5.0` на этом этапе.

## 7. MT-12 — DNS Health Failover

### 7.1 Disabled mode

Health Monitor выключен. Применить `beta-broken`, подождать минимум один monitoring interval.

PASS только если:

- DNS остаётся `192.0.2.1`;
- приложение не переключает профиль;
- Health сообщает Disabled;
- Agent не выполняет failover.

После проверки вручную вернуть `beta-good-cf`.

### 7.2 Healthy path

Настройки:

```text
Enabled: yes
Monitor interval: 15 seconds
Failure threshold: 2
Recovery threshold: 2
Cooldown: 30 seconds
Mode: Resolve only
Action: Notify only
Test domains: example.com, cloudflare.com
```

Минимальный interval 15 секунд является ожидаемой нормализацией сервиса.

Применить `beta-good-cf`, выполнить Health Check.

Ожидаемо: successful queries, рост consecutive successes, `Healthy` после recovery threshold, DNS profile не меняется.

### 7.3 Notify only

Оставить `Failure threshold = 2`, `Action = Notify only`, применить `beta-broken`.

После первой ошибки ожидается `Degraded`, `Failures: 1/2`.
После второй — `Failed`, `Failures >= 2`.

```powershell
Get-DnsClientServerAddress
```

PASS только если DNS остаётся `192.0.2.1`.

### 7.4 Fallback profile

Настроить:

```text
Action: Switch to fallback profile
Fallback: beta-good-cf
Failure threshold: 2
Cooldown: 30
```

Применить `beta-broken`; после threshold ожидается:

```text
beta-broken -> beta-good-cf
```

Проверить:

```powershell
Get-DnsClientServerAddress
Resolve-DnsName example.com
```

Также проверить `Last Failover`, `Last Action`, `Active Profile`, `Cooldown Until`.

### 7.5 Failover chain

Цепочка:

```text
beta-broken
beta-good-cf
beta-good-google
```

Action: `Switch to next profile`.

После threshold должен произойти `beta-broken -> beta-good-cf`; фактический DNS должен быть `1.1.1.1` / `1.0.0.1`.

Отдельно перестроить failure condition и подтвердить переход к следующему профилю цепочки. UI selection не является достаточным evidence — проверять `Get-DnsClientServerAddress`.

### 7.6 Cooldown

После состоявшегося failover снова создать failure condition до истечения cooldown.

PASS только если:

- повторное переключение не происходит;
- state отражает Cooldown;
- `CooldownUntilUtc` заполнен;
- после cooldown новый failover снова допустим.

### 7.7 Recovery threshold

После Failed/Degraded вернуть рабочий профиль при `Recovery threshold = 2`.

Первый успешный check не должен преждевременно давать full recovery; после второго ожидается `Healthy`.

Проверить counters и Last Failure.

### 7.8 Reboot persistence

Оставить Health Enabled с безопасным рабочим профилем, перезагрузить VM.

```powershell
Get-Service DnsSwitcherAgent
```

Проверить сохранение settings/state и продолжение worker без unhandled errors.

## 8. MT-11 — Split DNS / NRPT

### 8.1 Baseline и matching

До создания правил:

```powershell
Get-DnsClientNrptRule
```

Сохранить список. Приложение не должно удалять чужие NRPT rules.

Создать правило:

```text
Namespace: .example.com
Profile: beta-good-cf
Enabled: yes
```

До Apply встроенный Split DNS Test должен давать match для `example.com` и `www.example.com`, отсутствие match для `iana.org`.

Простое сохранение конфигурации не должно создавать Windows NRPT rule.

### 8.2 Apply

Apply Split DNS, затем:

```powershell
Get-DnsClientNrptRule |
    Format-List Name,DisplayName,Namespace,NameServers,Comment
```

Ожидается DnsSwitcher-managed rule с namespace `.example.com` и `1.1.1.1` / `1.0.0.1`.

### 8.3 Реальная namespace routing

Изменить только Split DNS rule:

```text
.example.com -> beta-split-broken
```

Apply, затем:

```powershell
Clear-DnsClientCache
Resolve-DnsName example.com
Resolve-DnsName iana.org
```

Ожидается failure/timeout для `example.com`, при этом `iana.org` продолжает разрешаться через обычный system DNS.

Не использовать `Resolve-DnsName -Server ...`, потому что это обходит проверяемую policy path.

### 8.4 Reset

Выполнить Split DNS Reset:

```powershell
Get-DnsClientNrptRule
Clear-DnsClientCache
Resolve-DnsName example.com
```

DnsSwitcher-managed rule должна исчезнуть, `example.com` снова разрешаться обычным system DNS.

### 8.5 Ownership safety

В elevated PowerShell создать foreign rule:

```powershell
Add-DnsClientNrptRule `
    -Namespace ".iana.org" `
    -NameServers "1.1.1.1" `
    -DisplayName "Beta Foreign NRPT Rule" `
    -Comment "Foreign test rule"
```

Далее создать и Apply DnsSwitcher rule, затем выполнить DnsSwitcher Split DNS Reset.

PASS только если DnsSwitcher rule удалена, а `Beta Foreign NRPT Rule` осталась.

Удаление foreign rule DnsSwitcher-ом классифицируется как `BLOCKER`.

После теста foreign rule удалить вручную.

## 9. MT-09 / MT-10 — Agent / Named Pipe path

При работающем Agent выполнить:

- DNS apply;
- Health failover;
- Split DNS apply/reset.

Не должно быть лишних UAC prompts; privileged operations должны проходить через Agent/Named Pipe.

### Agent unavailable

```powershell
.\cli\DnsSwitcher.Cli.exe service stop
```

Проверить non-elevated UI/CLI: нет зависания, ложного success или непонятного состояния.

Если есть elevated direct fallback, проверить его отдельно из elevated process.

После теста:

```powershell
.\cli\DnsSwitcher.Cli.exe service start
```

## 12. Классификация

### BLOCKER

Installer не устанавливается; приложение не запускается; DNS нельзя восстановить; Agent ломает систему; Split DNS Reset удаляет чужие NRPT rules; uninstall оставляет неработоспособную сеть.

### HIGH

Неверный failover profile; threshold/cooldown игнорируется; namespace уходит не на тот resolver; Apply/Reset сообщает success при другом Windows state.

### MEDIUM

Неверный status; state обновляется только после reopen; UI скрывает важную ошибку; настройка не сохраняется.

### LOW

Косметика, spacing, minor localization.

## 13. Исправление FAIL

Для каждого FAIL:

1. записать точные repro steps;
2. сохранить observed state/evidence;
3. определить root cause;
4. добавить automated regression test, где возможно;
5. внести минимальный fix;
6. повторить automated tests;
7. собрать новый installer;
8. повторить конкретный VM scenario;
9. выполнить smoke regression соседних сценариев.

После code fix уже протестированный `beta.1` binary не заменять молча. Следующий полностью пересобранный candidate — `v1.5.0-beta.2`.

## 14. Beta.1 exit criteria

`v1.5.0-beta.1` можно считать проверенной только если зафиксированы фактические PASS для:

- Release build/tests;
- clean VM installer и self-contained runtime;
- Agent install/start;
- DNS apply/reset;
- Health disabled, notify-only, fallback, chain, cooldown, recovery, reboot persistence;
- Split matching, NRPT apply, реальная namespace routing, reset и foreign-rule ownership safety;
- Agent path и Agent unavailable;
- MT-15 smoke;
- uninstall с удалением Agent и рабочим DNS после теста.

Stable release `v1.5.0` на этом этапе не создаётся.
