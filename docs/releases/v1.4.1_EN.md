## About this release

`v1.4.1` is a compatible stable patch release for Windows. It synchronizes application metadata, release script defaults, and artifact paths. It does not expand the user-facing feature set beyond `v1.4.0`, no `profiles.json` format change is declared, and no separate migration is required.

These notes were aligned with the current release standard after publication. The `v1.4.1` tag was not modified. The MIT license was added to the current development branch later and is not present in the historical tag.

## Highlights

- Version `1.4.1` is consistent across assembly metadata, portable packaging, and installer tooling.
- Portable ZIP and installer EXE use predictable `v1.4.1` directories and filenames.
- Desktop components can be located inside the `artifacts/release/v1.4.1/` package layout.

## Changes

### Changed

- `Version`, `FileVersion`, `AssemblyVersion`, and `InformationalVersion` are set to `1.4.1`.
- The default version in `scripts/publish-release.ps1` is set to `1.4.1`.
- The default version in `installer/build-installer.ps1` is set to `1.4.1`.
- Release documentation and the release checklist use `v1.4.1` artifact paths and filenames.
- Sibling desktop executable discovery includes the `v1.4.1` package path.

## Installation and updating

### New installation

1. Open [GitHub Release `v1.4.1`](../../releases/tag/v1.4.1).
2. For normal use on Windows x64, select the portable ZIP or installer EXE when the corresponding asset is published.
3. A framework-dependent package requires a compatible .NET 10 runtime.
4. Start `DnsSwitcher.Ui.exe` or the installed application and verify that the DNS profile list opens.

Final assets and a clean installation from them were not verified while updating this document.

### Updating

The release scope supports updating from `v1.4.0` to `v1.4.1`.

1. Back up `data/config/`.
2. Stop the Windows Agent when it is installed and running.
3. For a portable installation, extract the new version to a separate directory and move the saved `data/` directory.
4. For an installed version, run the `v1.4.1` installer and reinstall the Agent through the application's supported command when required.
5. Verify the selected profile, adapter, and current DNS status.

No configuration format change or mandatory Windows restart is declared for `v1.4.1`. An update from a final release asset was not performed during this documentation work.

### Rollback

1. Stop the Agent.
2. Restore the package or installer from the previous version.
3. Restore the `data/config/` backup.
4. Recheck the profile, adapter, and DNS status.

Rollback was not tested with final release assets.

## Known issues

No open GitHub issues were found during the documentation update. The project documentation records these limitations:

- Windows only;
- Agent installation and direct DNS changes require administrator privileges;
- Split DNS relies on Windows NRPT and can be bypassed by applications using their own DNS/DoH stack;
- the CLI is not fully localized;
- current UI screenshots are not published;
- final assets, installation, updating, and rollback were not revalidated while preparing these release notes.
