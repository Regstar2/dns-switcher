## About this release

- **Version:** `v1.5.0`
- **Channel:** stable
- **Date:** 2026-08-19
- **Previous version:** `v1.4.1`
- **Platform:** Windows x64
- **Compatibility:** in-place upgrade from `v1.4.1` without changing user profile or settings formats

`v1.5.0` completes the current DnsSwitcher desktop/tray workflow. It combines a configurable system-tray menu, refined primary windows, detailed About/Help surfaces, final RU/EN localization, and validated installer/portable delivery.

## Highlights

- **Configurable Tray** — optional action groups can be hidden in Settings and refresh without restarting Tray.
- **Refined UI** — Main, Settings, DNS Health Failover, and Split DNS were updated without changing their network contracts.
- **Health / About / Help** — primary service surfaces are directly available from the **More** menu.
- **Verified installer delivery** — stable SemVer selection is combined with mandatory SHA-256 verification before installer launch.
- **Self-contained delivery** — installer and portable ZIP do not require a separately installed .NET Desktop Runtime.

## Changes

### Added

- System-tray group visibility settings with backward-compatible defaults and live reload.
- Dedicated **About** and **Help** windows with complete RU/EN localization.
- Direct Health, About, and Help entries in the main **More** menu.
- Manual update checks and an opt-out automatic Tray check.
- Stable SemVer selection excluding draft and prerelease releases.
- Strict `DnsSwitcher-<version>-win-x64-setup.exe` and `SHA256SUMS.txt` selection.
- Windows CI and release workflow tying build/tests, installer, portable package, and checksums to one commit.

### Changed

- Refined Main, Settings, DNS Health Failover, and Split DNS UI.
- Tray status, Health, Split DNS, and Agent detail dialogs now use consistent RU/EN localization.
- Installed version is resolved from assembly metadata with `Directory.Build.props` as the canonical source.
- Installer and portable delivery use self-contained publishing.
- README and release documentation now reflect the final stable `v1.5.0` state.

### Fixed

- Removed duplicated punctuation from localized Tray status/details.
- Installer deployment no longer requires a separately installed .NET Desktop Runtime on the target machine.
- Packaging retains the bilingual README files and screenshot assets referenced by packaged documentation.

### Security

- The update client contains no PAT, OAuth token, or other embedded GitHub credential.
- The installer does not launch when the expected checksum entry is missing or SHA-256 verification fails.
- Update delivery accepts only expected HTTPS GitHub release URLs for the configured repository.

## Installation and updating

### New installation

1. Open [GitHub Release v1.5.0](https://github.com/Regstar2/dns-switcher/releases/tag/v1.5.0).
2. Download `DnsSwitcher-1.5.0-win-x64-setup.exe`.
3. Optionally verify SHA-256 against `SHA256SUMS.txt`.
4. Run the installer and complete setup.
5. Open DnsSwitcher and verify that **About** reports version `1.5.0`.

Portable package: `DnsSwitcher-1.5.0-win-x64.zip`.

### Updating

Validated upgrade path:

```text
v1.4.1 → v1.5.0
```

1. Close UI and Tray, or allow the installer to close running instances.
2. Run the `v1.5.0` installer over the existing installation.
3. The installer updates application files and refreshes the Agent runtime registration.
4. Start DnsSwitcher and verify version `1.5.0`.
5. Verify that profiles and user settings are preserved.

Preserved state:

- DNS profiles;
- app/UI preferences;
- Tray settings;
- DNS Health settings/state;
- Split DNS rules;
- Agent installation path is refreshed to the current installed version.

A normal upgrade does not require a Windows reboot.

### Automatic update checks

Settings provides a manual check, while Tray can check the stable channel automatically; automatic checks can be disabled. DnsSwitcher does not overwrite its own running binaries: after SHA-256 verification it launches the external Inno Setup installer through the standard Windows/UAC flow.

### Rollback

If needed, uninstall `v1.5.0` and manually install the previous installer. Preserve `data/config/` before a manual rollback; `v1.5.0` does not change the core profile or settings formats.

## Known limitations

Split DNS depends on Windows NRPT and can be bypassed by applications that use their own DNS/DoH stack.

Built-in update checks use only publicly readable GitHub Releases without embedded credentials. If the release source is unavailable to an anonymous client, the app reports a nonfatal update-source/network failure, and the release asset can still be installed manually after SHA-256 verification.
