# DnsSwitcher v1.5.0

[Русский](v1.5.0.md) · **English**

Status: final release candidate; the stable tag/release has not been published yet.

## Highlights

`v1.5.0` completes the current Windows desktop/tray workflow with configurable tray content, refined primary UI, direct Health / About / Help access from the **More** menu, and a secure update-delivery path without embedded GitHub credentials.

## What's new

- configurable system-tray groups with live reload;
- refined Main, Settings, DNS Health Failover, and Split DNS UI without changing network contracts;
- direct Health navigation from the main **More** menu;
- a dedicated **About** window with the installed version, capability/architecture summary, MIT license information, and GitHub link;
- a dedicated detailed **Help** window covering DNS profiles, adapters, diagnostics, Health Failover, Split DNS, Agent, Tray, import/export, Settings, updates, Config, and Logs with practical usage guidance;
- installed version resolved from assembly metadata;
- manual update check and opt-out automatic Tray check;
- stable SemVer selection excluding draft/prerelease releases;
- strict Windows x64 installer asset selection;
- temporary installer download with mandatory `SHA256SUMS.txt` verification;
- self-contained installer and portable delivery;
- general Windows CI and exact-commit release-candidate workflow.

## Updating

After publication, installed builds should update through the official Inno Setup installer. A discovered update is optional and can be deferred by the user.

The update client contains no PAT/OAuth/API secret. While the main GitHub repository is private, its production releases are not anonymously readable; this is a release blocker rather than a credential workaround.

## Validation

Previous beta candidate automation recorded Release build, unit/integration test, and packaging evidence for the beta commit. The user closed the beta validation phase; historical `NOT RUN` records are not rewritten retroactively.

The final candidate must separately pass `.github/workflows/ci.yml` and `.github/workflows/release-candidate.yml` on the exact final commit. New About/Help/Update UI has a dedicated manual smoke plan: [`../testing/v1.5.0-final-smoke.md`](../testing/v1.5.0-final-smoke.md).

## Known limitations

- production update source: `BLOCKED` while the repository/release source is not anonymously readable over HTTPS;
- final real screenshots: `BLOCKED`, Windows capture required;
- Split DNS remains NRPT-based and may be bypassed by applications with their own DNS/DoH stack;
- the exact minimum Windows version is not encoded as a dedicated project property.
