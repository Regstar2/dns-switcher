# v0.7.1 - Preparation for v0.8 Privileged Agent

## Goal

Remove the requirement to run `Tray`, `UI`, and routine `CLI` commands as Administrator.

The target user experience is:

- one-time elevation to install privileged support;
- no elevation for normal `status`, `apply`, `reset`, and tray actions;
- portable app data stays next to the application folder.

## Chosen Direction

Use a dedicated Windows Service:

- project name: `DnsSwitcher.Agent.Windows`
- transport: Named Pipes
- service responsibility: privileged DNS operations only
- client responsibility: config, validation, UI, tray, and command parsing

## Why Windows Service

This is the most direct way to remove repeated UAC prompts on Windows.

Rejected options:

- Always run `Tray/UI/CLI` elevated
  - simple, but poor UX and unsafe by default
- Elevate on every `apply/reset`
  - solves nothing for tray
- Scheduled task helper
  - workable, but less natural for always-available IPC and status checks

## Architecture

### New Projects

- `DnsSwitcher.Agent.Windows`
  - Windows Service host
  - owns the Named Pipe server
  - uses `DnsSwitcher.Infrastructure.Windows` to apply/reset DNS
- `DnsSwitcher.Contracts`
  - request/response DTOs for IPC
  - service error codes
  - protocol version

### Existing Projects After v0.8

- `DnsSwitcher.Cli`
  - non-elevated by default
  - sends `apply/reset` to the agent
  - keeps local commands like config validation
- `DnsSwitcher.Tray`
  - non-elevated
  - sends quick actions to the agent
- `DnsSwitcher.Ui`
  - non-elevated
  - full management surface
- `DnsSwitcher.Infrastructure.Windows`
  - keeps direct Windows DNS implementation
  - reused by the agent, not by tray directly for privileged actions

## Responsibility Split

### Local Client Side

- read `profiles.json`
- validate config
- select profile to apply
- render status and UX
- detect whether agent is installed/running

### Agent Side

- apply DNS profile to adapter
- reset adapter DNS to DHCP
- enforce privileged execution
- return structured errors to clients

## IPC Scope for v0.8 MVP

### Required Commands

- `Ping`
- `GetAgentStatus`
- `ApplyProfile`
- `ResetToDhcp`

### Optional in v0.8

- `GetDnsStatus`
- `ListAdapters`

For MVP, read-only status can still remain local if that keeps implementation simpler.

## Service Installation Model

The agent is installed once with elevation.

Expected flow:

1. User runs `dns-switcher service install` as Administrator.
2. Service is registered in SCM.
3. Service starts automatically or on demand.
4. `Tray/UI/CLI` use the agent without further UAC prompts.

## Important Portable Constraint

The app is portable, but a Windows Service is registered with an absolute executable path.

This means:

- moving the app folder breaks the registered service path;
- after moving the app, the user must reinstall the service.

This is acceptable, but must be documented and handled clearly in UX.

## Error Model

Clients must distinguish:

- agent not installed
- agent not running
- protocol version mismatch
- profile not found
- adapter not found
- adapter disabled
- privileged operation failed

## Security Notes

- Named Pipe must be local-only.
- The service should accept requests only from local interactive users.
- The protocol should carry only profile/adaptor identifiers, not arbitrary shell commands.
- The agent must never expose a generic command execution surface.

## v0.8 Implementation Backlog

1. Create `DnsSwitcher.Contracts`.
2. Create `DnsSwitcher.Agent.Windows`.
3. Implement Named Pipe server in the agent.
4. Implement Named Pipe client for `CLI`, `Tray`, and later `UI`.
5. Add CLI service commands:
   - `service install`
   - `service uninstall`
   - `service start`
   - `service stop`
   - `service status`
6. Route `apply/reset` through the agent when available.
7. Keep direct mode only for development fallback, or remove it fully after stabilization.
8. Add clear UX in tray when the agent is missing.

## Acceptance Criteria for v0.8

- `Tray` can switch DNS without running as Administrator.
- `CLI apply/reset` work without Administrator rights when the agent is installed and running.
- Routine switching does not trigger UAC.
- Missing agent produces a clear, actionable error.
- Service reinstall after moving the portable folder is documented.
