# Проверка целесообразности

Этот документ фиксирует только то, что можно подтвердить по существующему DnsSwitcher. Первоначальное исследование до реализации в репозитории не сохранилось и не реконструируется задним числом.

## Аналоги

Список и оценка альтернативных DNS-switching приложений в истории проекта не зафиксированы.

## Недостатки аналогов

Исторические выводы о недостатках конкретных аналогов отсутствуют. Добавлять их без исходного исследования было бы недостоверно.

## Отличие проекта

По текущему коду DnsSwitcher сочетает:

- WPF UI, tray и CLI поверх общих сервисов;
- локальные JSON-конфигурации;
- Windows Agent для привилегированных операций;
- DNS/site/benchmark диагностику;
- опциональные DNS Health Failover и Split DNS через NRPT;
- portable и installer сценарии поставки.

Это описание фактической реализации, а не утверждение об уникальности на рынке.

## Техническая реализуемость

Реализуемость подтверждается существующим solution, опубликованным `v1.4.1`, Windows-specific проектами и тестами. Текущая сборка использует .NET 10, а installer создаётся через Inno Setup.

## Платформенные и юридические ограничения

- проект ориентирован на Windows;
- изменение DNS и управление службой требуют административных прав;
- Split DNS зависит от возможностей Windows NRPT;
- проект распространяется по MIT License в текущей ветке;
- исторический tag `v1.4.1` был опубликован до добавления `LICENSE.md`.

Отдельное юридическое исследование DNS-провайдеров, корпоративных политик или требований конкретных стран в репозитории не зафиксировано.

## Инфраструктурные зависимости

Для обычной работы не заявлен обязательный внешний сервер DnsSwitcher. Конфигурация и логи хранятся локально.

Для разработки нужны .NET SDK и Windows-среда для полноценной проверки Windows-specific функций. Для сборки installer нужен Inno Setup 6.

## Риски

- Windows-specific функциональность ограничивает переносимость;
- реальные DNS, service, NRPT и installer сценарии требуют ручной проверки на Windows;
- поведение внешних DNS-серверов и сайтов находится вне контроля приложения;
- опубликованные assets нельзя считать проверенными только на основании сборочных scripts.

## Решение

Проект уже прошёл стадию MVP и имеет опубликованный patch release. Исходное формальное решение о запуске MVP в истории не сохранено, поэтому ретроспективные чекбоксы не заполняются.

Текущее состояние подтверждает, что проект продолжает использоваться как существующее Windows-приложение; дальнейшие версии должны получать отдельный подтверждённый scope до реализации.
