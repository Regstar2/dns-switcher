# Идея проекта

Этот документ описывает назначение DnsSwitcher ретроспективно по текущему коду, changelog и опубликованным версиям. Он не выдаётся за исходный документ планирования проекта.

## Проблема

Ручное изменение DNS в Windows требует повторяющихся действий с сетевыми адаптерами и системными настройками. Для регулярного переключения между наборами DNS-серверов дополнительно нужны воспроизводимые профили, проверка текущего состояния и понятный способ вернуть автоматическую конфигурацию.

## Целевая аудитория

Пользователи Windows, которым требуется регулярно переключать DNS-профили или диагностировать DNS-доступность. Текущий репозиторий не фиксирует более узкую первоначальную целевую аудиторию.

## Главный пользовательский сценарий

1. Выбрать сетевой адаптер.
2. Выбрать сохранённый DNS-профиль.
3. Применить профиль.
4. Проверить текущий DNS или выполнить диагностику.
5. При необходимости выполнить `reset` и вернуть автоматический DNS.

## Почему проект имеет смысл

DnsSwitcher объединяет один набор моделей и сервисов с несколькими пользовательскими клиентами: WPF UI, tray и CLI. Привилегированные операции могут быть вынесены в Windows Agent, а настройки остаются локальными.

Историческое сравнение с альтернативными продуктами в репозитории не зафиксировано, поэтому причины выбора DnsSwitcher вместо конкретных аналогов здесь не реконструируются.

## Что входит в MVP

По `CHANGELOG.md` первая зафиксированная версия `1.0.0` уже включала:

- общее ядро DNS-профилей, валидации, выбора адаптера и диагностики;
- Windows infrastructure для DNS, конфигурации и логирования;
- CLI, desktop UI и tray;
- привилегированный Windows Agent с Named Pipes;
- DNS- и site-диагностику;
- локальную portable-конфигурацию и логи;
- unit tests для основных правил и конфигурации.

Это ретроспективное описание фактической первой зафиксированной версии, а не восстановленный первоначальный backlog.

## Что не входит в MVP

В заметках `1.0.0` редактирование профилей через UI, полная локализация и dark theme ещё не считались завершёнными. Они были реализованы позднее и поэтому не должны задним числом включаться в исходный MVP.

DNS Health Failover, Split DNS и installer-поставка также относятся к более поздним версиям.

## Риски

- изменение системного DNS может временно нарушить сетевую доступность;
- часть операций требует прав администратора;
- реализация зависит от Windows APIs;
- Split DNS зависит от Windows NRPT и не контролирует приложения с собственным DNS/DoH;
- фактические сетевые сценарии невозможно полностью подтвердить только unit tests.

## Критерий успеха первой версии

Формальный исходный критерий успеха в доступной истории проекта не зафиксирован. Его нельзя достоверно восстановить без выдумывания исторического решения.

Фактически версия `1.0.0` в changelog фиксирует работающий набор клиентов, общее ядро, диагностику и тесты, а более поздние tags показывают продолжение проекта после этого этапа.
