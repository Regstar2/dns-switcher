# Engineering principles

- Сохранять существующую архитектуру DnsSwitcher: Core содержит модели/правила, Infrastructure.Windows — Windows/API/IO, UI и Tray — presentation.
- Делать зависимости явными и тестируемыми.
- Не создавать универсальные Manager/Helper/Utils без конкретной текущей пользы.
- Валидировать внешние данные на границе системы.
- Ошибки security-sensitive update flow должны иметь тип/код, а не определяться разбором случайной строки.
- Не проглатывать исключения молча; технические детали логировать, пользовательские сообщения локализовать.
- Не менять публичные контракты, config schema и network behavior без необходимости.
- Не добавлять package dependency, если стандартная библиотека решает задачу ясно и проверяемо.
- Комментарии объясняют инвариант/ограничение, а не очевидную строку кода.
- Public/nontrivial contracts документировать, когда без этого непонятны preconditions, lifecycle или security assumptions.
- При исправлении дефекта добавлять regression test либо воспроизводимый manual scenario.
